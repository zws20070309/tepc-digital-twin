# 代价轴与保真轴的实测账目（D-20 相关）

**各档之间所有已发布中心量逐位相同（逐位锁覆盖三档：归档侧 tableDistinct 与 ladderRunsMatchTheirGroups 在 N=400/N=2500 对含 publish 的全部腿去重，活体侧 tiersBitHarmless 四腿在 N=120 比 未设档/standard/screening/publish；两侧都未覆盖发货 nEvents=10000）；档位只改变不确定度陈述的存在与墙钟代价，不改变任何物理量。**
本页的存在理由：D-20 要"分级保真"，而本代理模型今天只有一条可测代价的显式切换轴，
且它**不是**保真轴。把这件事连同"其余候选轴为什么不成立"一起写下来，
是为了不让下一个人在同一批旋钮上再花几轮设计。

下面每格都标了三态之一：**已测否定**（有数字、有机理）、**有条件**（只在某个能区/工况下成立）、
**未测**（承认不知道，并指向它的前置任务）。

**取数口径（必须先读）**：§1 的三档比值**有归档产物**（见该节"出处"），并且已被
`tests/unit/test_uncertainty_depth_tiers.m` 按 (档, N) 逐项对账，可以按数字引用 —— 但**每个数只在自己那个 N 上成立**
（N=400 与 N=2500 两点都测了，比值明显不同，见 §1 的"比值随 N 变"那一段）。
§2 里标"已测"的数字现在分两类：**配对了归档产物的**（涨落那行 `straggling_production_mix_20260925T182013Z`、
采样时间那行 `ts_pair_20260925T214543Z`，都是 .json + .log 成对，第三方可在本仓库内按同 seed 复算）；
以及**只有量级、无归档产物的**（`waveform.enabled` 的 0.94×、§2 第四行机理里"场映射腿比解析地图贵 0.2–0.65 s/事件"、
`field.mode` 那行的时间，以及 §2 第一行里 N=400 的那三个 y_F 与 28.6/27.8/26.7 s）
—— 后者只能当**量级**用，不能当精度引用，这与 `docs/uncertainty_budget.md`
里 FEM 那一行用的是同一个限制口径。
机理侧的结论（绑定的是哪条约束、成本落在哪一段代码）不依赖这些数字，
它们由下面点名的仓库内文件与既有回归锁承担。

## 1. 已实现的显式切换：不确定度传播深度（不是保真）

| 档 | 生效值 | 中心量 | 墙钟（N=400，4 腿，已归档） | 墙钟（N=2500，2 腿，已归档） |
|---|---|---|---|---|
| `screening` | `uq.enabled=false` | 与 standard 逐位相同（已锁） | min 33.08 s / median 33.49 s ⇒ **0.555×** | min 52.52 s / median 57.67 s ⇒ **0.265×** |
| `standard` | `uq.enabled=true, nSamples=32` | 发货值（与未设档的链逐位相同，已锁） | min 60.24 s / median 60.32 s ⇒ **1.000×（基准）** | min 209.63 s / median 217.57 s ⇒ **1.000×（基准）** |
| `publish` | `uq.enabled=true, nSamples=128` | 不经任何中心量之手（归档侧与活体侧逐位锁都含它的腿，见 § 开头那句；两侧均未覆盖发货 nEvents=10000） | min 134.92 s / median 136.07 s ⇒ **2.256×** | min 690.07 s / median 697.24 s ⇒ **3.205×** |

**比值随 N 变，而且方向与先前预期相反**：两点各自内部算得 主循环 ≈ **28.9 s 固定开销 + 0.0115 s/事件**
（解两点方程：(57.67−33.49)/(2500−400)=0.01152，33.49−400×0.01152=28.88）；UQ 段（同 N 减去 screening 腿）
合到每样本每事件 ≈ **2.0–2.5 ms**（N=400：standard 26.84 s/(32×400)=2.10 ms、publish 102.58/(128×400)=2.00 ms；
N=2500：standard 159.90/(32×2000)=2.50 ms、publish 639.57/(128×2000)=2.50 ms）。
⇒ 关掉 UQ 的**节省占比随 N 上升**（N=400 省 44.5% ⇒ N=2500 省 73.5%），而不是"主循环线性涨所以占比被稀释"。
按两个跨点的斜率分解时，原因不在 UQ 变贵，而在 N=400 时那 28.9 s 固定开销占了 screening 腿的 86%，把比值压向 1。
这条是**事前写下预测再被打脸的**：预测写的是"比值会降到 1.64/2.01"，实测 3.77/12.09；错的根源是漏了固定开销
（过程记录 §17 留着原预测与算式，不改口）。
**第三个实测点给这条分解划了适用范围**（2026-09-26，`docs/test_evidence/ts_pair_20260925T214543Z.json`）：
一条 N=43000 的 standard 腿（`nSamples=32`，与 standard 档同工作量）实测 **279.7 s / 285.7 s**，
而按上面这套 (F≈28.9 s, m≈0.0115 s/事件, UQ 段≈160 s) 外推该是 **≈684 s** ⇒ 高估 **2.4 倍**。
（宿主条件 —— 开跑前 free 3852 MB、MATLAB 镜像行 2 = 独占 —— 记在**仓库外**的驱动日志里，
仓库内产物只含 N/seed/两腿 y_F/y_D/nEff/地板/Δ；按本节开头的口径，这部分**不算可复算精度**。）
两点定两参数，(400, 2500) 这对拟合**精确到 1e-13 s**（screening 与 standard 两条都精确复现），
所以问题只能在**外推**：模型残差 +0.6 s (N=400)、−2.7 s (N=2500)、**−210.2 s (N=43000)**。
把 standard 腿各自减掉同 N 的 UQ 段（N=43000 与 N=2500 的 `NEvPerSample` 都被 `execute.m` 的
`max(300, round(min(N,2000)))` 截到 2000、样本数都是 32 ⇒ 这两段的工作量逐位相同，取 159.9 s 是同一份计算），
得"主循环+固定" = 33.49 / 57.67 / 122.83 s，两两斜率 **0.01152** 与 **0.001608 s/事件**（相差 **7.2 倍**）。
⇒ 能落地的结论：**这条形式的外推资格已被否证**，出了 400–2500 就不能再拿来报价，新工作点必须实测。
三点的最小二乘拟合现算 F = **42.60 s**、m = **0.001878 s/事件**，残差仍有 **−9.9 / +10.4 / −0.5 s**
（最大残差 ≈ screening 腿的 31%）⇒ "常边际直线"这个形式在 400–43000 上确实拟合不动；
但**实测的两个跨点之间它是精确的**，塌掉的是外推，不是形式。
两句先前的话写重了，在此收回：其一，"主循环对 N 次线性"点不成立 —— 同一套 (28.88, 0.011519) 加上每样本 UQ 段
去预测 standard N=2500 会给 253.7 s 对实测 217.6 s（残差 −36.1 s），所以那 7.2 倍完全可能落在 UQ 项而不是主循环项，
现有三点分不开；其二，"否证"太重 —— 一次 2.4 倍的外推失败只够划定适用范围，那条分解在 400–2500 之内是精确的。
⇒ 处置：`28.9 s 固定 + 0.0115 s/事件` 降级为**只在 400–2500 两点之间成立的局部拟合**。
另外两句仍然成立：三档**比值**在 N>2500 没测（ts_pair 只有一个档、两条腿只差采样时间，给不出 screening/publish 的分母），
所以"比值随 N 回落"仍是推理不是测量；先前那句"N=6000 三档单腿 ≈ 34 min"是拿 N=400 的**每事件平均值**乘出来的
（把固定开销与已封顶的 UQ 段一起按线性放大，正是本节证明不可做的用法），它和任何由这条拟合算出的数字一样
**只算算术示例、不算证据**。
所以 `config/uncertainty_depth_tiers.json` 的 `cost_ratio_measured` 现在是**带 N 标签的数组**，
一个 N 一条，对账锁逐 (档, N) 与"同产物同 N 的 standard 分母"核对，任何一端都不许当常数用。

出处：`tools/uncertaintyDepthLadder.m` 的归档产物
`docs/test_evidence/uncertainty_depth_ladder_20260925T010100Z.json`
（`seeds=24680, pairs=2, ABBA, N=400, 12 条腿`）与
`docs/test_evidence/uncertainty_depth_ladder_20260925T185522Z.json`
（`seeds=24680, pairs=1, ABBA, N=2500, 6 条腿`，开跑前 free 4820 MB、MATLAB 镜像行 2 即独占）。
产物里三条硬事实，各自都有对账口径：

1. **同一 N 内跨档的 `y_F` 只有一个值**：N=400 那 12 条腿全是 `25.368973389393243`
   （`y_D` 同理 `42.339875470481395`），N=2500 那 6 条腿全是 `25.3194884099182`
   （`y_D=41.682043429297444`、`nEff=1908`）⇒ 在这批数据里"改档"与"改物理量"确实是两件事。
   `tests/unit/test_uncertainty_depth_tiers.m` 的 `tableDistinct` 现在按 **(产物, N)** 粒度去重 ——
   先前按整个文件去重是错的：两个工作点的 `y_F` 本来就该不同，按文件去重会把这条锁变成假红。
2. **`config_sha256` 去重后是 3 个**（一档一个）⇒ 只能证明三档的 cfg 互不相同；它**不是**"档位进了全链配置"的证据（三腿原始 cfg 本来只差 `run.uncertaintyDepth` 一个键，哈希必然不同，即使并档一行代码都没生效 —— 同文件 tiersBitHarmless 里就把"只比 sha"定为假判据），
   不是表里有、代码没读。
3. **比值与中位数一并被表引用**：`config/uncertainty_depth_tiers.json` 的
   `cost_ratio_measured` 是**数组**，每条形如 `N / legs / wall_min_s / wall_median_s / ratio_vs_standard / artifact`，
   同一用例逐 (档, N) 对账，且分母必须取**同产物同 N** 的 standard 分组 ⇒ 手改表里的数字会判红，
   改数字必须同时重跑阶梯；把同一条数字贴两遍（N 重复）也判红。

**对本页先前口径的一处更正**：§1 之前写着"同配置两腿墙钟离散 ±24%"，本批 4 腿 × 3 档的
实测极差只有 **0.65%–2.0%**（standard 60.24–60.63、publish 134.92–136.76、screening 33.08–33.74）。
差的来源**没有归档证据**：当时那批探针确实与套件同时在跑，但仓库里没有那批的产物可查，
所以"并发把抖动放大到 24%"只能当**推测**而不是已测机理。规范结论不依赖这个归因：
**墙钟只作记录、不作判据**（并发随时可能重新放大它，判据一律走逐位相等与同产物比值）。

机理（为什么改不了物理）：`src/+tepc/+run/execute.m` 的次序是
`buildSummary`（`:352`）→ `waveformStage` → `driftDiagnostic` → `runUqStage`（`:378`）→
写 `summary.json`（`:379`）。UQ 段只往 summary 加
`u_yF_rel / u_yF_CI95 / u_Dcum_rel / uq_status / uq_note / u_nSamples / u_nFailed /
u_n_out_of_domain / u_error` 这些**陈述类**字段，没有任何一个回流到中心量。
因此这一维的正确名字是"不确定度传播深度"，把它叫"保真档位"会把读者引向
"粗档 = 物理更糙"或"细档 = 更准"两种反向误读。

**这句话已经从"不下结论"升级为"两点已测"**：`execute.m:761` 的 `NEvPerSample = max(300, min(N, 2000))`
使 UQ 侧的每样本事件数在 N>2000 封顶。先前这里写"节省占比随 N 升降**不下结论**，只在两个工作点各测一次"，
现在两点测完了，结论是**省得更多**（44.5% → 73.5%），机理与算式见本节开头"比值随 N 变"那一段。
仍要保留的限制有两条，且第三条**已被实测改写**：两点之间的中间 N 没有实测（那套"固定 + 边际 + 每样本边际"分解已被 N=43000 那个点否证，
见本节开头，所以它连"模型值"都算不上，只在 400–2500 之间内插勉强可用）。原先写的"N>2500 之后比值必然回落（`NEvPerSample` 已封顶而主循环继续涨）但回落形状没测"
现在第三点 N=10000 已测（`uncertainty_depth_ladder_20260926T202822Z`：screening 0.3351、publish 2.7227，即形状确实是**先降后升/先升后降**的方向），
但**三点合不成一条标度律**：N=2500 的 standard 中位 217.6 s、publish 697.2 s 反而大于 N=10000 的 183.9 s 与 500.6 s（事件数 4 倍却更快），
同 seed 的单链重测已把责任定在**旧的 N=2500 那次**：它给出 standard 147.09 s、publish 475.55 s、screening 40.99 s（旧读数是 217.57 / 697.24 / 57.67，慢了 1.43–1.47 倍），产物 `uncertainty_depth_ladder_20260926T221145Z.json`，表里三条 N=2500 元素已改指它，旧产物 185522Z 保留作"这次污染"的证据。修正后三点的绝对墙钟随 N 单调（standard 147.1→183.9、publish 475.5→500.6、screening 41.0→61.6），比值 screening 0.555→0.279→0.335、publish 2.256→3.233→2.723 ⇒ 「节省占比先升后降」与 `NEvPerSample` 在 N>2000 封顶的机理一致，可引用；但可引用的仍是**比值形状**，不是每事件绝对代价的标度律。
另须记一笔条件偏离：N=10000 那次用的是 `minFreeMb=2000`（起批 free_mb=2324、单链），不是工具缺省的 3500。

## 3. 计数地板的算法（防止把偏差埋进噪声）

`u_yF = sqrt(y_D/y_F − 1) / sqrt(n_eff)`，**分子分母必须取自同一次 run**
（`docs/uncertainty_budget.md` 场来源那一行明令禁止跨 run 拼 CV 与 n_eff，并写着早先拼出来的 2.1% 已废）。
按那批 N=400 探针腿各自的比值实算得 4.68 / 4.71 / 4.73%（nEff 296–305）—— **这三个数是未归档的一次性探针**
（见开头"取数口径"），只能当量级；下面所有反解都改用**有归档产物**的那一对同 run 数（ladder 010100Z 的
y_F=25.368973389393243、y_D=42.339875470481395、nEff=301 ⇒ 4.714%）作锚点。
换一次 run 就要用那次 run 的 y_F/y_D/n_eff 重算 —— 同一公式在
y_F=19.3589、y_D=34.4627 的一次 **40 事件** 运行上按它自身 nEff=29 给 16.4%（这一样也没有归档产物）。
所以"≈4.7%"是本批腿的量级，不是常数。

两个必须随数携带的限制：
1. 一次 N=400 的比对分辨不出 2.35%（该数是粗档对**最细档 5e-9** 的比，不是对发货档），这是**统计功效**的限制，不是"Ts 无关紧要"的证据。
2. 反解要重算一遍才敢引用。按本节开头那对**同 run** 的数 (y_F=25.368973389393243、
   y_D=42.339875470481395、nEff=301) 现算 CV = √(y_D/y_F − 1) = **0.8179**，u = 4.714%；
   要把 u 压到 2.35% 需要 nEff = (0.8179/0.0235)² ≈ **1211**，按 nEff/N≈0.7525 换 N ≈ **1610**；
   把判据取成"效应 > 2 倍标准差"即 u ≤ 1.175%，需要 nEff ≈ **4845**（N ≈ 6440）——
   是 1σ 需求的 **4 倍**，不是"翻倍"（u ∝ 1/√nEff，u 减半 ⇒ nEff ×4）。
   **口径要写清**：这两条都是"单腿自己的 u 与效应比"的口径；若是**两条独立腿互相比**，差的 σ 是 √2 倍单腿 u，
   同样的判据要 nEff 再 ×2（下面第 3 条用的就是两腿口径）。
   本文件先前写的"nEff 约 4060（对应 N≈5400）"用这条例子**复算不出来**（无论按 1σ 还是 2σ 反解），
   属未经核实的旧数，已按现算更正；4060 与 5400 之间自洽（0.7525×5400≈4062），
   只是它锚的那个 CV 在归档产物里找不到出处（同 run 现算的 CV 是 0.8179 ⇒ 1211 / 4845，两个口径都不是 4060）。
   换算用的 nEff/N 现在有五个实测比值：N=40→29（0.7250）、N=400→301（0.7525）、N=2500→1908（0.7632）、
   N=43000 两腿→31859 与 32160（0.7409、0.7479）。**它不恒定**：跨度 0.725–0.763（+5.3%），
   而同一个 N 的两条腿（同 seed、只差 Ts）也差 301 个有效事件（0.94%）—— 这个差的本节标准误没算，
   所以只记作"比值不恒定"的证据，不记作机理。所以拿 0.7525 换 N 是一阶近似，换出来的 N 自带 ~2–3% 的系统余量（方向：大 N 处比值偏低，
   同一目标 nEff 需要的 N 比按 0.7525 算的多 ~1%）。幂次没被这批数据否证（系数是否漂也测不出来，0.81–0.82 全落在散布带里）：CV 在 N=400 腿是 0.8179、N=43000 两腿 0.81065 / 0.81544，
   ⇒ "地板 ∝ 1/√nEff" 站得住，站不住的是"nEff 与 N 成正比"。
   但 N≈1600/6400 这两个工作点本身仍**没跑过**：跑掉的是 §2 第一行那对 N=43000。
3. 每事件代价的口径也要改。**0.066 s/事件在这批产物里没有出处**（产物里最省的 screening
   也是 33.49 s / 400 = 0.0837 s/事件）。按同一归档产物的各档中位数现算：
   screening **0.0837**、standard **0.1507**、publish **0.3402** s/事件。
   据此，把可分辨效应压到 2.35%（N≈1600）单腿约 **2.2 min**（screening）到 **4.0 min**（standard）；
   压到 2σ（N≈6400）单腿约 **9 min**（screening）到 **16 min**（standard），两腿对照约 **33 min**。
   先前那句"15 次这样量级的运行约 1.5 小时、本仓库决定不花这笔算力"是挂在 0.066 与 5400 上的，
   数换了之后这个决定**要重算而不是沿用**，而重算把它推翻了：上表那三个"每事件"是 **N=400 的平均值**，
   里面 86% 其实是每次 run 的固定开销（2500 那批解出来：固定 ≈28.9 s、主循环边际 0.0115 s/事件、
   UQ 段 2.0–2.5 ms/(事件·样本)，见 §1"比值随 N 变"那段）—— 拿平均值乘大 N 会把代价高估一个量级。
   按分解重算：`validate.m:136` 的 `TS_TOO_COARSE` 是 **warn 不是 error**（阈值 `Ts > shaping_s/50`，
   发货 1e-6 ⇒ 2e-8），所以**不带警告的**对照只有 2e-8↔1e-8 这一对。要在 2σ 上把一对**真** 1.28% 的差分辨出来，
   每腿计数地板得压到 1.28%/(2√2) = **0.453%** ⇒ nEff ≥ (0.8179/0.004525)² ≈ **3.3×10⁴** ⇒ N ≈ **4.3 万**。
   （先前这里印的是 `(0.8179/0.0064)² ≈ 3.3×10⁴`，那个除数配不出这个数 —— 0.0064 漏了两腿那个 √2，
   它只能给 1.6×10⁴；判据取 1.28%/(2√2) 才对得上 N≈4.3 万，已按现算改回。）
   **这一对已经真跑了**（2026-09-26：同 seed 24680、N=43000、两腿只差 `electronics.sampleTime_s`，
   产物 `docs/test_evidence/ts_pair_20260925T214543Z.json` + 同名 .log）。实测 nEff 31859 / 32160 = 设计目标，
   两腿合成地板 **0.643%**，实测相对差 **+0.59%** ⇒ **0.92 倍地板，2σ 判据下分辨不出**。
   于是"效应量 +1.28%"这个说法本身要收回：N=400 那次读数落在 4.7% 的地板里，它从来只是抽样。
   高 N 这次比对给出的**差值** 95% 区间 ≈ **−0.70% … +1.88%**（= delta ± 1.96×合成地板，只含**计数抽样**误差，
   不含任何模型形式差；+1.28% 被包在里头，既没被确认也没被排除）。
   代价这一栏也被同一批数据改了口径：按"固定+边际"外推的**每腿 680 s / 两腿 23 min**，实测是
   **279.7 s 与 285.7 s、两腿合计 9.4 min** —— 高估 **2.4 倍**。
   要分清"什么被推翻、什么没有被"：被推翻的是**拿 N=400 的每事件平均值去乘大 N**这种用法（本节上面那三个
   0.0837 / 0.1507 / 0.3402 s/事件是产物中位数的商，作为 N=400 那一格的算术仍然成立，只是**不许**再当单价用）；
   所以本节把这三格标成"局部单价"，新工作点必须实测。
   ⇒ 处置因此换了理由：不再是"本仓库决定不花这笔算力"（这一对只花了两腿 9.4 分钟，第一次跑还因判定分母用错而作废，
   连同排队约 50 分钟 —— 算力从来不是障碍），而是**买了也没换来档位** —— 分辨 0.59% 需要每腿 nEff 再放大 **5 倍**
   （N≈2.2×10⁵；按 2500↔43000 斜率外推两腿 ≈19 min，这条外推用的正是刚被划定适用范围的那类拟合，只能当量级、**未测**），
   而即使钉死也只是往预算表里添一行 ≲1% 的数，中心量照样随 Ts 移动、照样违反 §1 的立表前提"所有档中心量逐位相同"。
   这一维因此停在 §2 第一行的 **已测否定（不作档位）** + 一句"合法档差的 2σ 上限 +1.9%，量级已约束、点值未钉死
   （0.6% 这个量还分不出）"。
   "计算自由度尚未换算成预算份额"这句话仍然成立，D-20 也仍是 PARTIAL。

### §4.1 拆分后的实测（2026-09-30，同机同会话，判据一字未改）
把 `test_pipeline.m` 里两条**需要多次完整 run** 的用例（`test_reproducibility` 3 次 execute、
`test_resume_bit_exact` 3 次 execute）搬到新文件 `tests/integration/test_pipeline_rerun_equivalence.m`，
理由是上面的静态定位：成本杠杆是 execute 调用次数（每次约 28.9 s 固定开销），不是 N。

三条不可省略的读法：
- **总时长没有变小**（234.3 + 598.5 = 832.8 s vs 858.1 s；25.3 s 之差是同机两次测量的抖动，
  不是收益）。拆分买到的只有**记账粒度**：最重单文件从 858.1 s 降到 598.5 s（1.43 倍），
  其余部分 234.3 s，所以按文件粒度发预算的认证能在同样的预算里推进更多文件。
- 刻意**没有**把两条用例合并共用一次 run：那会削弱「换 seed 必须改变发布谱」与「续跑位精确」
  各自独立的断言，属于降低覆盖。
- 搬动用例会让静态计数与证据清单过期（实测：`test_doc_counts` 的 manifest 与同代两条子锁各红一次），
  所以拆分必须同批跑 `genCounts` + `writeLatestEvidence`。当前事实：
